# Тесты GRASS «Передача смены»

## 1. Логика (быстро, нужен только Node.js)

```
npm test
```
Проверяет график, границы 08:30/20:30, время смен, предыдущую/следующую смену и цепочку передачи,
свой график смен из Настроек (1.7.6), а также расчёты статистики и сводки (`stats.js`), расписания регламента
(`reglament.js`), журнал смены (`journal.js`), ленту комментариев (`comments.js`) и выгрузку в Excel/PDF (`export.js`).
Эти же тесты запускаются в `RELEASE_*.bat` и в сборке GitHub перед выпуском установщика.

## 2. Сквозные тесты интерфейса (стенд)

Настоящие `main.js` + `preload.js` + `index.html` + SQLite в браузере Chromium,
с подменой времени и честными перезапусками. Electron не нужен.

Нужно: Node.js 22+, Python 3.10+, `pip install playwright` и `python -m playwright install chromium`.

```
python dev-tests/e2e/tests_e2e.py .                        # все R/B/F-тесты
python dev-tests/e2e/tests_e2e.py . b07                    # один тест по имени
python dev-tests/e2e/tests_e2e.py . M                      # только общая база (1.7.2)
python dev-tests/e2e/tests_e2e.py . H                      # только «Надёжность» (1.7.3)
python dev-tests/e2e/tests_e2e.py . S                      # только «Скорость и мелочи» (1.7.4)
python dev-tests/e2e/tests_e2e.py . D                      # только новый дизайн (1.7.5)
python dev-tests/e2e/tests_e2e.py . G                      # только регламент (1.7.6); так же J K Q P W X
python dev-tests/e2e/tests_e2e.py . T                      # только статистика 1.7.7
python dev-tests/e2e/tests_e2e.py . V                      # только правки истории 1.7.8
python dev-tests/e2e/tests_e2e.py . Y                      # только защита от сбитых часов 1.7.9
python dev-tests/e2e/tests_e2e.py . Z                      # только 1.7.11
python dev-tests/e2e/tests_e2e.py . E                      # только «Безопасность» (1.7.12)
python dev-tests/e2e/tests_e2e.py . L --prev <папка прошлой версии>   # база прошлой версии и откат на неё (1.7.11)
python dev-tests/e2e/tests_e2e.py . U --base161 <папка 1.6.1>   # обновление базы со старой версии
```

- **R** — поведение, которое должно сохраняться (регрессии)
- **B** — исправленные баги 1.6.1 (на 1.6.1 падают, на 1.7 проходят)
- **F** — новые функции 1.7 (исполнитель, вложения, компактное окно)
- **N** — изменения 1.7.1 (автоархив, статистика, сохранение только изменённого)
- **M** — общая база в терминале (1.7.2): несколько копий программы на одной базе — видимость, конфликты, «Принять все», личные настройки, первый запуск, ошибки настройки, резервные копии, 10 копий одновременно
- **H** — «Надёжность» (1.7.3): приёмка по одной и возврат, непринятые передачи, полная история правок, дневная копия по таймеру, ротация копий, вторая папка, проверка базы и восстановление при повреждении, плашка при ошибке сохранения
- **S** — «Скорость и мелочи» (1.7.4): Архив и История по 50 карточек с историей при раскрытии, обновление только по кнопке с копией базы, дата создания при восстановлении, смена не по графику, свои окна вместо confirm/alert, сводка сама и «Ознакомлен», красный баннер просрочки, метка «кочует», карточка «Мои» и поиск по комментариям и истории, удаление файлов очищенного архива
- **D** — новый дизайн (1.7.5): группы «Просрочено / Скоро срок / Остальные» и свёрнутые выполненные, быстрые действия при наведении (пишут в историю то же, что окно), тусклые нули и пульс просрочки, жёлтая плашка перед передачей и её настройка, плотность «Обычно / Компактно» у каждого технолога своя, пустой экран, ни одна кнопка и поле 1.7.4 не пропали (список `ids_1.7.4.txt`), кнопки статуса согласованы со списком
- **G** — регламент (1.7.6): задача по расписанию с автором «Регламент» и сроком, без дублей после перезапуска и при нескольких копиях на общей базе, «пропущен повтор», задним числом не создаётся, пауза/правка/удаление шаблона, «Из шаблона»
- **J** — журнал смены (1.7.6): запись, правка и удаление видны, только своё и только в свою смену, площадки раздельно, общая база, блок в сводке смены, поиск
- **K** — лента комментариев (1.7.6): новый не затирает старый, у старых задач комментарий — первая запись, быстрые кнопки ленту не трогают
- **Q** — статистика «Скорость и сроки» (1.7.6)
- **P** — график смен в Настройках (1.7.6): превью, проверка, подтверждение, история правок, общий для площадок и копий
- **W** — уведомления (1.7.6): за N до срока (личная настройка), о передаче моей смене и мигание, число просроченных на значке
- **X** — выгрузка в Excel и PDF (1.7.6): сводка смены и статистика
- **T** — статистика 1.7.7: быстрые периоды (до минуты для «Моей смены»), фильтр по бригаде, клик по цифре и столбику — список задач и переход к задаче, строка «Всего» и сортировка, подсказка над столбиком, запоминание выбора у каждого технолога, выгрузка за выбранный период и бригаду
- **V** — правки 1.7.8: срок в истории на момент события (у выполненной — «в срок» / «с опозданием на …», не растёт), смена у автоархива — та, что на дежурстве, дата нового срока при восстановлении, вопрос при сроке в прошлом
- **Y** — 1.7.9: часы перевели назад — новые записи по настоящему времени и плашка «часы отстают», при нормальных часах плашки нет, склонения (минута/минуты/минут, час/часа/часов, день/дня/дней, задача/задачи/задач)
- **Z** — 1.7.11: вёрстка всех экранов на 1280 / 1600 / 1920 px в будний день и в воскресенье (текст не наезжает на текст —
  проверка `layout_check.js`), ни одна кнопка и поле 1.7.10 не пропали (список `ids_1.7.10.txt`) и каждый файл окна попадает
  в установщик, 10 копий одновременно создают, передают, удаляют и разом принимают передачи (без потерь и дублей), проверка
  последней резервной копии (по кнопке и каждый день), мягкое обновление (копия новее работает — старая не пишет),
  незнакомые поля задачи переживают правки, подпункты (кто и в какую смену, история, две копии сразу), объявление площадки,
  «Слежу за задачей», окно «Что нового»
- **E** — «Безопасность» (1.7.12): ни одна кнопка и поле 1.7.11 не пропали (`ids_1.7.11.txt`, снят с настоящей 1.7.11),
  учётка Windows в каждой записи истории (пишет main.js, из окна не подделать), окно «Кто вы?» и закрепление технолога
  за учёткой (только свободные имена, чужое не выбрать ни в окне, ни в обход; «Отвязать» и удаление — только админ),
  общая база без списка админов — как раньше, 10 человек под своими учётками, опасные вложения, права админа и вторая
  папка из `grass-config.json`, защита окна (sandbox, CSP, запрет переходов, новых окон и разрешений, «Открыть
  выгрузку» только своей), файл настройки только из ProgramData, без автообновления на сервере, предохранители
  Electron в сборке, `npm ci` на GitHub и RELEASE-BAT своей версии
- **L** — 1.7.11, только с `--prev <папка прошлой версии>`: база прошлой версии открывается новой без потерь, а после отката
  на прошлую версию подпункты новой не теряются; 1.7.12 — откат на прошлую версию после новой колонки учётки
  в истории и закреплений на общей базе
- **U** — обновление базы и бэкапов с 1.6.1

С 1.7.12 окно на стенде открывается с той же защитой (CSP), что и в программе, и любое её нарушение (встроенный
скрипт, обработчик) считается ошибкой теста. Строковые условия `wait_for_function` стенд передаёт функцией — иначе
Playwright вычислял бы их через eval, который CSP запрещает. У каждой копии на общей базе может быть своя «учётка
Windows» (`GRASS_TEST_OS_USER`); тестовые переменные main.js слушает только у стенда и при запуске из исходников —
установленная программа их не видит.

Весь набор одной командой (логика, стенд и откат на прошлую версию):

```
sh dev-tests/run_all.sh ..\GRASS_Передача_смены_v1.7.11
```

На Windows стенд (с 1.7.10) останавливает main.js штатно — командой `QUIT` в stdin (как закрытие окна:
before-quit → снятие сессии), потому что SIGTERM там не доставляется. Страницы для порчи базы в тестах H
считаются через `node:sqlite` (`db-leaf-pages.js`): в Python sqlite3 на Windows нет `dbstat`.
На Linux/macOS остановка по-прежнему через SIGTERM.

Часовой пояс: браузер стенда всегда работает по Волгограду, а main.js и Python — по поясу компьютера.
На рабочих ПК он и так волгоградский. На машине с другим поясом запускай с `TZ=Europe/Volgograd`.

## 3. Живая проверка собранной программы (1.7.11, дополнено в 1.7.12, только Windows)

```
npm run dist:win
python dev-tests/live/live_check.py                         # dist\win-unpacked\GRASS-Peredacha-smeny.exe
python dev-tests/live/live_check.py <путь к exe> <папка для скриншотов>
```
Настоящий Electron из `dist\win-unpacked`: запуск на пустой базе → задача «Передать по смене» → закрытие крестиком и
перезапуск → копия, файл базы испорчен, «Восстановить копию» в системном окне Windows → восстановление из Настроек →
все экраны и версия → (1.7.12) учётка Windows в истории, в окне нет Node.js и работает CSP, предохранители exe
(`electron-fuses read`), копия exe с подменённым `app.asar` не запускается, `ELECTRON_RUN_AS_NODE` не выполняет
скрипт, `GRASS_CONFIG_FILE` и `GRASS_TEST_OS_USER` установленная программа не слушает. Скриншоты — в `..\проверка_<версия>\` рядом с папкой версии. Около 20 секунд; на экране мелькают окна.

Программа запускается с отдельным временным профилем (`--user-data-dir`), поэтому установленная программа и её база
(`%APPDATA%\grass-shift-handover`) не затрагиваются — скрипт сверяет профиль до и после. `GRASS_CONFIG_FILE` здесь
намеренно не используется: он записал бы в профиль пользователя пометку «общая база», и установленная программа
перестала бы открываться без файла настройки. (С 1.7.12 сценарий 7 нарочно запускает exe с `GRASS_CONFIG_FILE` —
во временном профиле — и проверяет, что установленная программа эту переменную не слушает.)

## 4. Замер сохранения на большой базе

```
python dev-tests/e2e/perf_save.py .                      # 5000 задач, 40 000 событий
python dev-tests/e2e/perf_save.py <папка 1.7.0> .         # сравнить две версии
```
Печатает время запуска, время одной правки, сколько данных ушло из окна в main.js за одно сохранение,
и (с 1.7.4) время отрисовки Истории, Архива (1500 задач в архиве) и поиска по главному списку.
