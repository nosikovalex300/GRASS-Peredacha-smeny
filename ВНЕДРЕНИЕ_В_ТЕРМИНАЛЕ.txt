GRASS — Передача смены · общая база на терминальном сервере (с версии 1.7.2, дополнено в 1.7.3 и 1.7.12)
============================================================================

Как это работает
----------------
Программа ставится на терминальный сервер один раз для всех. Каждый технолог запускает её
в своём сеансе терминала под своей учёткой. Все копии программы работают с ОДНОЙ базой
в общей папке на локальном диске сервера. Задачи других технологов появляются у всех
в течение 3 секунд. Если двое правят одну задачу, программа не даёт затереть чужую правку:
второй увидит свежую версию и сообщение, кто и когда её изменил.

Смена и площадка у каждого пользователя свои — они хранятся в профиле пользователя
(%APPDATA%\grass-shift-handover\grass-user.json), а не в общей базе.
Список технологов и настройки автоархива — общие.

С версии 1.7.12 в каждой записи истории сохраняется учётка Windows, под которой её сделали
(в истории задачи — подсказка у имени автора). Учётку записывает сама программа, из окна её
не подменить. Если в файле настройки указаны администраторы (шаг 3), технолог закрепляется
за своей учёткой (см. «Закрепление технолога за учёткой»).

Без файла настройки (см. шаг 3) программа работает как раньше: личная база в профиле.


Шаг 1. Установка (администратор сервера)
----------------------------------------
Установить «для всех пользователей» в Program Files. Проще всего — из командной строки,
запущенной от имени администратора:

    GRASS-Peredacha-smeny-Setup-1.7.12.exe /allusers

Установщик сразу ставит программу для всех в C:\Program Files\GRASS — Передача смены\
(без ключа он спрашивает «Для всех / Только для меня» — выбрать «Для всех пользователей»).
Тихая установка без окон:  GRASS-Peredacha-smeny-Setup-1.7.12.exe /allusers /S
Папку Program Files пользователи изменить не могут, поэтому подменить программу им нельзя.
Дома установка по-прежнему «только для меня», без прав администратора.


Шаг 2. Папка для общей базы
---------------------------
Создать папку на ЛОКАЛЬНОМ диске сервера, например:  D:\GRASS\data
Права на неё — только группе технологов (команды — в разделе «Безопасность», п. 1):
программа создаёт в ней файлы базы (grass.db, grass.db-wal, grass.db-shm),
папки backups и attachments.

Нельзя класть базу в сетевую папку на ДРУГОМ компьютере или на NAS: файл базы может повредиться.


Шаг 3. Файл настройки
---------------------
Создать файл  C:\ProgramData\GRASS-Peredacha-smeny\grass-config.json  такого содержания
(образец — grass-config.example.json):

    {
      "dataDir": "D:\\GRASS\\data",
      "admins": ["Ivanov", "Petrov"],
      "backupMirrorDir": "E:\\GRASS-mirror"
    }

- dataDir — папка общей базы (обязательно).
- admins — учётки Windows администраторов программы (без домена или как DOMAIN\Ivanov,
  регистр не важен). Только они могут: восстановить базу из копии, удалить файлы очищенного архива,
  удалить технолога, отвязать технолога от учётки. Без admins всё как в 1.7.11 (это могут все,
  закрепления технолога за учёткой нет).
- backupMirrorDir — вторая папка для копий (необязательно). Если задана здесь, в Настройках её
  нельзя ни поменять, ни отключить.

Обратная косая черта в этом файле пишется двойной (\\) — или можно писать D:/GRASS/data.
С 1.7.12 файл читается ТОЛЬКО отсюда (рядом с программой больше не ищется).
Пользователям нужно только чтение папки C:\ProgramData\GRASS-Peredacha-smeny — запись запретить
(команда — в разделе «Безопасность», п. 1), иначе любой технолог впишет себя в admins.
Файл лежит вне папки программы, поэтому переустановка и обновление его не трогают.


Шаг 4. Первый запуск
--------------------
Первый, кто запустит программу, увидит вопрос:
  - «Начать с чистой базы» — пустая база (так договорились при внедрении);
  - «Загрузить существующую базу…» — выбрать файл grass.db (или копию из папки backups);
    вложения из папки attachments рядом с ним переносятся тоже.
Остальные в это время ждут; вопрос задаётся один раз.

Проверка: Настройки → «Данные и резервные копии»: режим «Общая база (терминал)»,
файл базы в D:\GRASS\data, в строке «Сейчас работают» — кто ещё открыл программу.


Закрепление технолога за учёткой (1.7.12, если в настройке есть admins)
-----------------------------------------------------------------------
При первом запуске под учёткой программа спрашивает: «Вы вошли как <учётка>. Кто вы?» —
в списке только ещё не занятые имена (или «Меня нет в списке» — вписать себя).
После подтверждения «Закрепить за собой? Поменять потом сможет только администратор»
программа всегда сама открывается под этим технологом; выбрать чужое имя нельзя.
Перепривязать: администратор в Настройках → «Технологи» нажимает «Отвязать» у нужного
технолога; при следующем запуске под той учёткой программа снова спросит «Кто вы?».
Удаление технолога администратором тоже снимает закрепление.


Обновление программы
--------------------
На сервере автообновления нет совсем: если есть grass-config.json, программа не обращается
к серверу обновлений ни при запуске, ни по кнопке. Дома — как раньше.
  1. Попросить всех закрыть программу (кто работает — видно в Настройках).
  2. Установить новую версию поверх, для всех пользователей (шаг 1).
Если новой версии нужно обновить структуру базы, а кто-то ещё работает в старой, программа
не станет обновлять базу и покажет, кто её не закрыл. Старая версия, увидев обновлённую базу
или копию программы новее, перестаёт сохранять изменения и просит перезапуск (ничего не портит).


Резервные копии и восстановление
--------------------------------
- Раз в день программа сама делает копию базы в D:\GRASS\data\backups (хранятся 14 ежедневных
  и 10 ручных; копии перед обновлением структуры базы не удаляются).
  Копию делает одна копия программы на всех. Ручная копия — Настройки → «Создать копию».
- Настройки → «Вторая папка для копий» (или backupMirrorDir в файле настройки): лучше другой диск
  сервера или общий диск. Раз в день туда копируется база и новые вложения. Если папка недоступна —
  программа предупредит и продолжит работать. Копии в ней видны в списке «Восстановить из бэкапа».
- Раз в день программа проверяет базу и свободное место на диске (меньше 500 МБ — предупреждение).
  Если файл базы повреждён, программа предложит восстановить последнюю копию, а испорченный файл
  сохранит рядом как grass-broken-<дата>.db. С admins это предложение видит только администратор.
- Не копируйте grass.db руками, пока программа открыта: копируйте файлы из папки backups.
- Восстановить базу из копии можно, только когда с ней больше никто не работает —
  иначе программа откажет и назовёт, кто ещё в ней. С admins — только администратор.


Безопасность (для администратора сервера, 1.7.12)
==================================================
Все команды — в командной строке ОТ ИМЕНИ АДМИНИСТРАТОРА. Пути D:\GRASS\data, E:\GRASS-archive —
примеры, подставьте свои. Группы указаны через SID (*S-1-5-...), чтобы команды работали на русской
Windows: S-1-5-18 — СИСТЕМА, S-1-5-32-544 — Администраторы, S-1-5-32-545 — Пользователи.

Важно понимать: технологам нужно право изменения на папку базы, иначе программа не сможет писать.
Значит, технолог, который очень захочет, может испортить или удалить файл базы руками. Поэтому
главная защита — копии, до которых технологи не дотягиваются (п. 2 и 3), и журнал (п. 5).

1. Отдельная группа технологов и права только ей на папку базы

    net localgroup GRASS-Tech /add /comment:"Технологи GRASS - Передача смены"
    net localgroup GRASS-Tech Ivanov /add
    net localgroup GRASS-Tech Petrov /add
    icacls "D:\GRASS\data" /inheritance:r /grant:r "*S-1-5-18:(OI)(CI)F" "*S-1-5-32-544:(OI)(CI)F" "GRASS-Tech:(OI)(CI)M"
    icacls "D:\GRASS\data"

  Файл настройки — только чтение для пользователей:

    mkdir "C:\ProgramData\GRASS-Peredacha-smeny"
    icacls "C:\ProgramData\GRASS-Peredacha-smeny" /inheritance:r /grant:r "*S-1-5-18:(OI)(CI)F" "*S-1-5-32-544:(OI)(CI)F" "*S-1-5-32-545:(OI)(CI)RX"

  (В домене вместо локальной группы удобнее доменная группа — тогда её имя в icacls: DOMAIN\GRASS-Tech.)
  Новому технологу: net localgroup GRASS-Tech <учётка> /add — и перезайти в сеанс.

2. Копия от служебной учётки задачей Планировщика в закрытую папку
  Закрытая папка — только СИСТЕМА и администраторы, технологи её не видят:

    mkdir "E:\GRASS-archive"
    icacls "E:\GRASS-archive" /inheritance:r /grant:r "*S-1-5-18:(OI)(CI)F" "*S-1-5-32-544:(OI)(CI)F"

  Файл C:\ProgramData\GRASS-Peredacha-smeny\archive-copy.cmd (создать в Блокноте, кодировка ANSI):

    robocopy "D:\GRASS\data\backups" "E:\GRASS-archive\backups" *.db /XO /R:2 /W:5 /NP
    robocopy "D:\GRASS\data\attachments" "E:\GRASS-archive\attachments" /E /XO /R:2 /W:5 /NP
    forfiles /P "E:\GRASS-archive\backups" /M *.db /D -90 /C "cmd /c del @path"
    exit /b 0

  Копируются готовые копии программы из backups (они целые), а не сам grass.db. Копии старше 90 дней
  удаляются. Задача каждый день в 23:30 от учётки СИСТЕМА:

    schtasks /Create /TN "GRASS\Копия в закрытую папку" /SC DAILY /ST 23:30 /RU SYSTEM /RL HIGHEST /TR "C:\ProgramData\GRASS-Peredacha-smeny\archive-copy.cmd"
    schtasks /Run /TN "GRASS\Копия в закрытую папку"
    dir "E:\GRASS-archive\backups"

  Восстановление из закрытой папки: администратор копирует нужный файл grass-*.db из
  E:\GRASS-archive\backups в D:\GRASS\data\backups и выбирает его в «Восстановить из бэкапа».

3. Теневые копии тома (VSS) — «Предыдущие версии» папки базы

    vssadmin add shadowstorage /for=D: /on=D: /maxsize=10%
    schtasks /Create /TN "GRASS\Теневая копия D" /SC DAILY /ST 13:00 /RU SYSTEM /RL HIGHEST /TR "vssadmin create shadow /for=D:"
    vssadmin create shadow /for=D:
    vssadmin list shadows /for=D:

  (vssadmin create shadow есть только в Windows Server. Можно и мышкой: свойства диска D: →
  «Теневые копии» → «Включить» и «Параметры» → расписание.) Восстановить: свойства папки
  D:\GRASS\data\backups → «Предыдущие версии». Теневая копия — не замена п. 2: она на том же диске.

4. BitLocker — шифрование диска с базой (на случай кражи диска или сервера)

    powershell -Command "Install-WindowsFeature BitLocker -IncludeAllSubFeature -IncludeManagementTools -Restart"
    manage-bde -status
    manage-bde -on C: -RecoveryPassword
    manage-bde -on D: -RecoveryPassword
    manage-bde -autounlock -enable D:
    manage-bde -protectors -get D:

  Ключ восстановления (48 цифр из последней команды) записать и хранить отдельно от сервера
  (в домене — сохраняется в AD). Без него при сбое данные не достать. Первая строка нужна только
  на Windows Server, на ней будет перезагрузка. Авторазблокировка D: требует, чтобы был зашифрован C:.

5. Аудит доступа к папке базы — кто удалил или сменил права (журнал «Безопасность»)

    auditpol /set /subcategory:{0CCE921D-69AE-11D9-BED3-505054503030} /success:enable /failure:enable
    powershell -Command "$a=Get-Acl 'D:\GRASS\data' -Audit; $sid=New-Object System.Security.Principal.SecurityIdentifier('S-1-1-0'); $r=New-Object System.Security.AccessControl.FileSystemAuditRule($sid,'Delete,DeleteSubdirectoriesAndFiles,ChangePermissions,TakeOwnership','ContainerInherit,ObjectInherit','None','Success,Failure'); $a.AddAuditRule($r); Set-Acl 'D:\GRASS\data' $a"
    powershell -Command "(Get-Acl 'D:\GRASS\data' -Audit).Audit"

  Первая строка включает аудит «Файловая система» (по коду — работает и на русской Windows).
  Пишутся удаления и смена прав (события 4660, 4663, 4670 в журнале «Безопасность»).
  Запись в базу не аудируется специально: программа пишет в неё на каждое действие — журнал
  переполнился бы. Кто что менял в задачах — видно в истории самой программы (имя и учётка).
  Размер журнала побольше:  wevtutil sl Security /ms:1073741824

6. Антивирус на папку вложений
  Windows Defender на сервере должен быть включён (папку attachments из исключений НЕ убирать):

    powershell -Command "Get-MpComputerStatus | Select RealTimeProtectionEnabled,AntivirusSignatureLastUpdated"
    schtasks /Create /TN "GRASS\Проверка вложений" /SC DAILY /ST 03:00 /RU SYSTEM /RL HIGHEST /TR "\"C:\Program Files\Windows Defender\MpCmdRun.exe\" -Scan -ScanType 3 -File D:\GRASS\data\attachments"

  Программа с 1.7.12 сама не даёт прикреплять exe, bat, cmd, js, vbs, ps1, lnk, msi, reg, jar,
  документы с макросами (docm, xlsm, pptm) и т.п., а такие файлы, прикреплённые раньше, не открывает
  (только «Показать в папке»). Если антивирус тормозит работу с базой, можно исключить только файлы
  базы (не вложения):  powershell -Command "Add-MpPreference -ExclusionPath 'D:\GRASS\data\grass.db','D:\GRASS\data\grass.db-wal'"

7. Что ещё сделано в самой программе (1.7.12)
  - Окно программы изолировано (sandbox, запрет чужих скриптов, переходов, новых окон и запросов
    разрешений); «Открыть выгрузку» открывает только файл, который программа сама только что сохранила.
  - В exe выключен запуск как Node.js и отладка (--inspect, NODE_OPTIONS), включена проверка
    целостности app.asar: подменённый файл программы не запустится.
  - Подпись exe — позже, когда ИТ выдаст сертификат.


Если что-то не так
------------------
- «Не найден файл настройки общей базы» — пропал grass-config.json (шаг 3). Программа специально
  не открывает пустую личную базу, чтобы никто не решил, что задачи пропали.
- «Нет доступа на запись к папке общей базы» — проверить права (шаг 2, п. 1 «Безопасности»):
  учётка в группе GRASS-Tech? Перезашла после добавления в группу?
- «Файл настройки общей базы повреждён» — ошибка в JSON (часто одинарная \ вместо \\).
- «… может только администратор программы» — действие разрешено только учёткам из admins (шаг 3).
- Технолог выбрал себя не того — администратор: Настройки → «Технологи» → «Отвязать».
- Красная плашка «Изменения не сохранены…» — база была недоступна; программа повторяет
  сохранение каждые 5 секунд. Не закрывайте программу, пока плашка не сменится на «сохранены».
