GRASS — Передача смены · версия 1.7.12 «Безопасность»
=====================================================

Основа: 1.7.11. Структура базы: версия БД та же (6), добавлена только одна колонка — учётка Windows в истории
(task_history.os_user). 1.7.12 ставится поверх 1.7.11 (и 1.7.10 … 1.7.2). Откат на 1.7.11 возможен установкой:
1.7.11 новую колонку просто не читает, закрепления технологов не видит и работает как раньше (проверено тестом
на настоящей 1.7.11: база 1.7.11 → 1.7.12 → 1.7.11 → 1.7.12, дома и на общей базе).

Ни одна кнопка, поле, окно и экран 1.7.11 не пропали (тест по списку ids_1.7.11.txt, снятому с 1.7.11).
Все изменения закрыты автотестами (см. dev-tests\README.md).
Итого: 18 R + 14 B + 11 F + 10 N + 14 M + 10 H + 10 S + 7 D + 6 G + 5 J + 2 K + 1 Q + 2 P + 3 W + 2 X + 7 T + 3 V + 3 Y
+ 11 Z + 11 E = 150 на стенде (Windows), 2 L (база 1.7.11 и откат на неё) и 48 юнит-тестов логики,
живая проверка собранной программы (7 сценариев) — всё зелёное.


ДЛЯ ТЕХНОЛОГОВ
--------------

1. Учётка Windows в каждой записи истории
   Программа сама записывает, под какой учёткой Windows сделано каждое действие. В истории задачи — подсказка
   при наведении на имя автора: «Учётка Windows: …». Из окна программы учётку не подменить.

2. На сервере технолог закреплён за своей учёткой (если администратор включил — см. ВНЕДРЕНИЕ)
   При первом запуске: «Вы вошли как <учётка>. Кто вы?» — выбрать себя из свободных имён (или «Меня нет
   в списке») и подтвердить. Дальше программа сама открывается под вашим именем; выбрать чужое нельзя.
   Ошиблись — к администратору, он «Отвяжет». Дома и на сервере без списка администраторов — как раньше.

3. Опасные файлы не прикрепляются
   exe, bat, cmd, com, scr, js, vbs, wsf, hta, ps1, lnk, msi, reg, jar, документы с макросами (docm, xlsm, pptm…),
   образы дисков (iso, vhd) и т.п. — с понятной причиной. Если такой файл прикрепили раньше, «Открыть» его не
   запускает, а рядом есть кнопка «Показать в папке».

4. Только у администратора (на сервере со списком администраторов): восстановление базы из копии, удаление
   файлов очищенного архива, удаление технологов, перепривязка. Кнопки на месте — программа отвечает,
   что это может только администратор. Дома всё как раньше.


ЗАЩИТА ПРОГРАММЫ
----------------

5. Окно программы изолировано: песочница (sandbox), запрет чужих и встроенных скриптов (CSP — основной скрипт
   окна теперь отдельный файл app.js), запрет переходов на чужие страницы, новых окон и любых запросов
   разрешений. «Открыть выгрузку» открывает только файл, который программа сама только что сохранила.
6. Предохранители exe: нельзя запустить как Node.js, NODE_OPTIONS и --inspect не действуют, проверяется
   целостность app.asar — подменённый файл программы не запускается (проверено на собранном exe).
7. Файл настройки общей базы читается только из C:\ProgramData\GRASS-Peredacha-smeny\grass-config.json
   (рядом с exe больше не ищется); тестовые переменные окружения установленная программа не слушает.
   В нём же теперь: список администраторов (admins) и вторая папка для копий (backupMirrorDir).
8. На сервере (есть grass-config.json) автообновления нет совсем. Дома — как раньше.
9. Electron обновлён до 45.1 (было 38.8). Сборка на GitHub — npm ci по package-lock.json.
10. Для администратора сервера в ВНЕДРЕНИЕ_В_ТЕРМИНАЛЕ.txt — раздел «Безопасность» с готовыми командами:
    группа технологов и права только ей, копии в закрытую папку задачей Планировщика, теневые копии (VSS),
    BitLocker, аудит доступа к папке базы, антивирус на вложения; установка «для всех» (/allusers).
    Подпись exe — позже, когда ИТ выдаст сертификат.
